## 需求背景

平台端在模型标注、训练详情查看等场景中，用户需要频繁切换图像。当前正式环境中，切换图像或保存标注后进入下一张时存在明显等待感。

已观察到的实现特征：

1. 标注页和训练详情页的画布图像均直接使用 `selectedRow.fileRecordVO.readPath`。
2. 切换图像时会驱动标注画布重新加载图像、绑定标注数据并重绘。
3. 保存当前标注并跳转下一张时，会提交标注结果，并重新请求待标注列表和已完成列表。
4. 左侧图像列表未看到虚拟滚动配置，数据量较大时可能产生额外渲染和表达式计算成本。
5. 生产环境中前端静态资源和低代码页面 JSON 的缓存策略偏保守，部分 hash 资源仍使用 `no-cache` 或 `max-age=0`。

因此，图像切换慢不应只视为网络问题，而应作为“图像加载链路 + 标注保存链路 + 页面运行时渲染 + 静态资源缓存”的整体性能优化需求处理。

## 设计目标

1. 单纯切换图像时，用户应在可感知范围内快速看到目标图像，避免长时间白屏或画布空白。
2. 保存标注并进入下一张时，优先保证连续标注流畅，不因全量刷新列表打断操作节奏。
3. 大图、慢网和大量图片列表场景下，页面应有稳定的加载反馈和可恢复状态。
4. 优化策略需要兼容现有训练数据、标注数据和图像存储方式，避免影响训练结果准确性。
5. 形成可被开发和测试拆解验证的性能指标与实施路径。

## 设计范围

### 本次包含

1. 标注画布图像加载策略。
2. 图片预加载和前端图像缓存策略。
3. 标注保存后的列表更新策略。
4. 左侧图像列表的渲染优化策略。
5. 生产静态资源和图像资源缓存策略。
6. 切图过程中的加载反馈和异常反馈。

### 本次不包含

1. 标注工具能力重构，例如新增标注形状、快捷键体系或多人协同标注。
2. 训练算法和训练任务调度优化。
3. 图像存储架构整体迁移。
4. 平台端整体低代码运行时替换。

## 设计结论

### 1. 图像资源分层

标注和训练查看不应无条件直接加载原图。建议为每张训练图像提供三类访问地址：

1. 缩略图：用于左侧列表、文件夹预览、快速定位。
2. 预览图：用于标注画布和训练详情默认展示，建议限制最长边，例如 1600 或 2048 像素。
3. 原图：用于下载、放大查看、必要的精细确认或后续算法处理。

页面默认加载预览图，只有用户主动查看原图或放大到超过预览图清晰度阈值时，再请求原图。

### 2. 切图时预加载相邻图片

进入标注页或训练详情页后，系统应维护一个轻量图片缓存池：

1. 当前图像加载完成后，后台预加载下一张和上一张。
2. 连续标注模式下，优先预加载后续 2 至 3 张待标注图像。
3. 切换到文件夹子图时，优先预加载同一文件夹内相邻图像。
4. 缓存池需要设置上限，避免一次性加载过多大图占用内存。

推荐默认缓存策略：

1. 当前图像：必须保留。
2. 前一张：保留，用于误切返回。
3. 后两张：优先保留，用于连续标注。
4. 超出 4 至 6 张后按最近使用淘汰。

### 3. 保存标注后采用增量更新

保存当前标注并进入下一张时，不建议每次都全量刷新待标注和已完成列表。

推荐流程：

1. 用户点击保存或下一张。
2. 前端立即锁定当前图像的保存状态，展示轻量保存中状态。
3. 提交 `/api/train/annotationPic`。
4. 保存成功后，前端本地将当前图像从待标注移动到已完成，或更新当前图像的标注状态。
5. 直接切换到已预加载的下一张图像。
6. 后台低频校准列表数据，例如每完成 10 张、切换标签页、页面重新进入时再全量刷新。

只有以下情况需要立即全量刷新：

1. 保存接口返回数据冲突。
2. 当前图片已被删除或训练任务状态发生变化。
3. 用户手动点击刷新。
4. 切换待标注/已完成标签页。

### 4. 列表渲染虚拟化

左侧图像列表和文件夹子列表应支持虚拟滚动或分段渲染。

规则：

1. 图片数量超过 100 张时启用虚拟滚动。
2. 文件夹展开时只渲染可视区域内的子项。
3. 选中态、标注状态和展开态使用稳定 `id` 作为 key。
4. 切换图像时只更新当前行和上一行，不触发整列表重绘。
5. 列表中的图片统一使用缩略图，不使用原图地址。

### 5. 图片 URL 和缓存稳定

图片读取地址应尽量稳定，避免同一图片每次切换都生成不同 URL。

服务端建议：

1. 内容不变的图片返回稳定 URL。
2. 配置 `ETag` 或 `Last-Modified`。
3. 对训练图片、缩略图、预览图配置合理缓存时间。
4. 如果必须使用临时授权 URL，应保证同一次页面会话内 URL 不频繁变化。

前端建议：

1. 按图片 `fileRecordVO.id` 建立缓存映射，而不是仅按 URL。
2. 图片加载失败时保留当前选中状态，提供重试入口。
3. 切图时先展示上一张或骨架态，不出现长时间空白画布。

### 6. 静态资源缓存优化

生产环境中带 hash 的前端资源可以使用长期缓存。

建议：

1. `index.html` 保持 `no-cache`，确保入口能获取最新版本。
2. `/platform-frontend-pc/assets/*` 使用 `Cache-Control: public, max-age=31536000, immutable`。
3. 低代码页面 JSON 如果路径可随版本发布变化，也使用长期缓存；如果路径固定，至少使用短时缓存和 ETag。
4. JSON、JS、CSS 均开启 gzip 或 brotli。

### 7. 可感知加载反馈

切图超过 200ms 时展示轻量加载态，超过 1s 时展示明确加载反馈。

建议反馈：

1. 画布右上角显示小型加载标识，不遮挡已有标注。
2. 左侧目标图片行显示加载中状态。
3. 保存标注时按钮进入保存中，避免重复提交。
4. 图片加载失败时显示“重新加载”入口，不自动跳过当前图像。

## 页面与交互规则

### 页面结构

1. 左侧列表继续承担图片定位、待标注/已完成切换和文件夹展开。
2. 中间标注画布为主区域，默认展示预览图。
3. 画布加载图像时保留容器尺寸，避免布局跳动。
4. 原图查看入口可放在画布工具区，例如“查看原图”或缩放到阈值后提示加载原图。

### 操作流程

#### 单纯切换图片

1. 用户点击左侧图像。
2. 立即更新选中态。
3. 如果目标图像已在缓存中，直接显示。
4. 如果未缓存，展示画布加载态并请求预览图。
5. 图像加载完成后绑定标注数据并重绘。
6. 后台预加载相邻图像。

#### 保存并下一张

1. 用户完成标注后点击保存或下一张。
2. 当前图像进入保存中状态。
3. 保存成功后本地更新当前图像状态。
4. 直接切到下一张待标注图像。
5. 后台根据策略进行低频列表校准。

### 状态与反馈

1. 图片加载中：画布显示轻量 loading，左侧目标行保持选中。
2. 图片加载失败：画布显示重试，不改变当前选中图像。
3. 标注保存中：保存按钮禁用并显示保存中。
4. 保存失败：停留当前图像，保留本地标注内容，提示用户重试。
5. 后台校准列表失败：不打断当前标注，仅在列表区域提示刷新失败。

### 校验与异常

1. 当前图像未加载完成时，不允许提交标注。
2. 保存期间不允许重复提交同一张图。
3. 如果下一张图已不存在，应跳到下一张可用图，并提示列表已更新。
4. 如果训练任务状态已变化为训练中或已完成，应退出编辑态并提示状态变化。

## 数据与权限影响

1. 图片接口需要返回缩略图、预览图和原图地址，或提供可按尺寸请求的图片服务。
2. 图片资源需要支持缓存头配置，不影响鉴权安全。
3. 标注保存接口可以保持不变，但前端不再依赖保存后立即全量刷新。
4. 如果后端支持增量接口，可新增按图片 ID 获取最新状态的轻量接口。

## 性能验收指标

建议以生产近似环境验证：

1. 已缓存相邻图像切换：目标图像 200ms 内可见。
2. 未缓存预览图切换：目标图像 800ms 内可见。
3. 保存并切下一张：保存接口成功后 300ms 内切到下一张。
4. 500 张训练图片列表滚动和切换不卡顿，点击切换不触发整列表明显重绘。
5. 图片加载失败、保存失败、列表校准失败均可恢复，不丢失当前标注内容。

## 待确认项

1. 后端是否已有缩略图或预览图生成能力。
2. 当前 `readPath` 是否为稳定 URL，是否存在临时签名或动态 query。
3. 标注画布使用预览图是否会影响用户对缺陷细节的判断，是否需要一键切原图。
4. 保存标注后，本地移动待标注/已完成状态是否与现有任务统计规则一致。
5. 低代码运行时是否支持列表虚拟滚动；如不支持，是否需要局部自定义组件承接该页面。
6. 生产资源缓存策略由前端、低代码发布服务、Nginx 或对象存储中的哪一层负责配置。
