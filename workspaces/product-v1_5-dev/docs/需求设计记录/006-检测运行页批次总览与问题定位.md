# 006 检测运行页会话统计与检测项平铺

## 基本信息

- 状态：设计中，Demo 已实现
- 提出日期：2026-07-09
- 最近更新：2026-07-13
- 对应 Demo：`demo/client.html`
- 相关页面：客户端检测工具运行页、检测记录

## 需求背景

当前检测运行页原先以单张图像轮播为核心，用户需要等待页面自动切换才能看到不同采图项的结果。实际生产现场更关心的是当前检测工具从进入运行到退出前的整体运行情况，以及本次检测周期里所有采图项是否都正常出图、哪个采图项 NG 或异常。

当采图项较多时，左侧列表和中间主图之间需要来回对应，定位效率低。运行页中的标签信息目前没有明确使用场景，相机查看也和采图项关联不够清晰，导致页面信息显得松散。

## 关键定义

“检测会话”指用户进入某个检测工具并启动运行后，到退出工具前的所有检测累计。它更接近当天或当前班次在这个工具下的运行汇总，不等同于一次触发检测周期。

“单次检测周期”指一次触发后完成的一组采图、处理、检测和规则判断。一个检测会话内会包含多次检测周期。

## 设计目标

1. 用户进入检测运行页后，能直接看到当前检测会话的累计情况。
2. 单次检测周期内的所有采图项同时可见，不再依赖轮播切换。
3. 检测前为空卡片，检测中为加载态，检测完成后原位显示图像和 OK/NG/异常结果。
4. 当出现 NG 或异常时，用户能直接在平铺卡片中定位问题图像项。
5. 相机查看入口提升到页面上方，支持查看当前工具关联的所有相机。
6. 移除检测运行页中暂无实际运行场景的标签信息。

## 设计范围

### 本次包含

1. 检测运行页顶部改为工具级操作栏，不再显示“检测会话”标题。
2. 会话统计移动到页面标题栏，减少中部和右侧运行区域的信息挤占。
3. 运行时长与运行模式合并到工具标题旁，作为低存在感的页面状态组件。
4. 工具级相机查看入口和“结束检测”放到页面顶部操作栏，相机入口需要表达连接/掉线状态。
5. 主区域改为检测项平铺卡片。
6. 检测完成后停止自动轮播，直接展示所有采图项。
7. 检测运行页移除标签信息板块和独立相机信息板块。

### 本次不包含

1. 后端真实会话 ID、班次、工单号统计。
2. 检测记录详情页结构重构。
3. 齿轮场景的角度维度结构化展示。
4. 运行趋势、节拍曲线或长期统计看板。

## 设计结论

1. 页面顶部左侧展示线条返回图标、工具名称和完整统计卡片；右侧展示相机查看入口与“结束检测”。
2. 会话统计作为一张完整横向卡片放入标题栏，包含运行时长、检测数量、良品率、OK 数、NG 数和异常数；检测数量按完整检测周期计数，不按单个检测项计数。不再展示批次状态、当前图像项、当前子图和问题定位。
3. 右侧运行面板采用窄栏布局，包含“检测 / 重置”、“最近检测记录”和“本次节拍”。“本次节拍”表示当前检测周期从第一项开始检测到最后一项完成检测的耗时。
4. “检测 / 重置”放在右侧运行面板内，尺寸需要适配窄栏，不占用过多纵向空间。
5. 相机查看入口按当前工具关联相机去重展示，放在页面顶部右侧，使用绿/红状态点表达连接/掉线，不直接显示连接状态文字。
6. 主区域标题为“检测项”，所有采图项以卡片平铺：
   - 等待检测：空白占位卡片。
   - 检测中：空白占位卡片叠加加载标识。
   - 检测完成：显示图像、检测项名称和一处大尺寸总结果标记。
7. 检测项卡片需要始终铺满主区域，按数量决定栅格：1 项 1x1、2 项 2x1、3 项 3x1、4 项 2x2、5-6 项 3x2、7-8 项 4x2、9-12 项 4x3，超过 12 项按 4 列滚动。
8. 检测项主卡片需要为底部检测项名称保留稳定空间，避免采图项较多时图像区压缩标题导致文字遮挡。
9. 检测项主卡片不展示相机、参数组、全图/子图标识；但需要将检测结果框回绘到主图，让用户能在主界面看到 NG 或缺陷位置。
10. 不再自动轮播单张图像，避免用户被动等待切换。
11. 检测触发后由按钮状态和检测项加载态反馈，不再显示“已模拟外部信号触发”等全局成功提示。
12. 检测运行页点击检测项卡片即可打开详情，不再额外显示“查看详情”按钮。
13. Demo 检测触发按顺序推进图像项：每次点击“检测”只触发一个图像项，该项先显示检测中，出结果后原位显示结果；再次点击后推进到下一个图像项。所有图像项从开始到结束算一个完整检测周期，只有完整周期结束后才更新检测数量、良品率和 OK/NG/异常统计。
14. “最近记录”只展示当前会话中可完整显示的记录，超出部分通过“查看全部”进入检测记录抽屉查看。
15. 进入工具或刷新页面后，若当前会话已有检测结果，应从会话记录恢复已检测图像项，不应变为空白或在下一次检测时才补回。

## Demo 实现记录

- 实现状态：已完成轻量原型
- 验证结果：
  1. 顶部工具栏已放置返回、工具信息、相机入口和结束检测。
  2. 会话统计已精简为运行时长、检测数量、良品率和 OK/NG/异常计数，并以完整卡片形式移入页面标题栏。
  3. 运行时长已合并到统计卡片，不再单独显示运行模式组件。
  4. 检测和重置已改为右侧运行面板中的独立按钮，底部显示本次节拍。
  5. 相机入口已放回顶部，并使用状态点表达连接/掉线。
  6. 检测项结果已改为平铺卡片，每项仅保留一处大尺寸总结果标记。
  7. 检测中显示加载态，检测项按点击顺序逐项出结果，完整周期结束后才累计会话统计。
  8. 检测触发过程已取消重复的全局成功提示。
  9. 主图卡片已支持齿轮齿面框和背板缺陷框回绘。
  10. 当前会话记录恢复逻辑已修正，重新进入工具后已检测项保持可见。
- 已知差异：
  1. Demo 使用本地会话开始时间和进入工具时的记录基线进行前端聚合。
  2. 真实产品需要由后端提供会话开始时间、结束时间、检测周期数和状态聚合。

## 待确认项

1. 检测会话是否需要显示班次、工单号、产品型号或操作员。
2. 采图项较多时，是否需要支持只看 NG/异常。
3. 齿轮场景中，平铺卡片是否进一步按角度或相机分组。
