# 007 客户端操作反馈分级规范

## 基本信息

- 状态：设计中，Demo 已实现
- 提出日期：2026-07-10
- 最近更新：2026-07-10
- 对应 Demo：`demo/client.html`
- 相关页面：客户端全局、检测运行页、采图页、配置弹窗

## 需求背景

客户端原有交互把大量常规操作结果统一显示为右下角反馈条，包括保存成功、切换成功、检测触发、列表刷新和下载触发等。连续操作时提示会重复堆叠并遮挡工作区，也使真正的校验失败、运行阻断和系统异常失去辨识度。

检测运行页中，触发检测后按钮、检测项加载态和结果卡片已经能够表达当前状态，再显示“已模拟外部信号触发”属于重复反馈。

## 设计目标

1. 减少不必要的全局提示，让运行画面保持稳定、干净。
2. 操作结果优先由按钮、列表、卡片或弹窗自身状态表达。
3. 让警告、错误和需要用户处理的信息具有明确优先级。
4. 避免连续信号或重复点击产生相同提示堆叠。

## 反馈分级

| 场景 | 反馈方式 | 示例 |
| --- | --- | --- |
| 同步操作成功且结果立即可见 | 静默，由原位置更新表达 | 修改名称、保存参数、删除后列表刷新、切换页面 |
| 运行过程 | 使用控件和内容区状态，不显示全局提示 | 检测中、采图中、模型下载中 |
| 异步任务完成且页面缺少明显结果 | 允许显示一次轻量成功通知 | 云端同步完成、Demo 下载任务开始 |
| 输入校验和前置条件不满足 | 显示警告通知；后续优先改为字段内提示 | 未填写名称、未选择图像、参数超限 |
| 当前操作被系统阻断 | 显示错误通知或常驻顶部告警 | 存储不足、客户端离线、模型加载失败 |
| 高风险或不可逆操作 | 使用二次确认弹窗 | 删除、解绑、结束检测 |

## 交互规则

1. 不再使用右下角反馈条，临时通知统一位于页面顶部居中，不遮挡主要操作区。
2. 常规数据保存成功默认不显示通知。
3. 检测信号触发后，只通过检测按钮状态、检测项加载态和最终结果表达过程，不显示额外成功提示。
4. 相同文案的通知在上一条消失前只显示一次。
5. 警告、错误和成功使用不同颜色，但保持相同尺寸和位置，避免形成新的视觉噪声。
6. 持续性系统问题不使用临时通知反复提醒，应进入顶部常驻告警区。
7. 通知不承担操作历史记录职责；需要追溯的信息进入检测记录、日志或任务列表。

## Demo 实现记录

- 常规 `persistState` 操作已改为成功静默，仅在本地缓存写入失败时显示错误。
- 已移除检测触发、图片切换、编辑模式切换、相机刷新、设备搜索和模型回填等重复成功提示。
- 下载与云端同步作为无明显页面结果的异步动作，保留一次顶部成功通知。
- 临时通知已从右下角移动到顶部居中，并支持成功、警告、错误三种状态。
- 相同通知已支持自动去重，避免连续触发堆叠。

## 后续优化

1. 将弹窗表单中的“请输入”“请选择”等校验逐步下沉到对应字段下方。
2. 为模型下载、云端同步等长任务提供任务状态或进度入口后，可继续减少成功通知。
3. 将相机、模型服务、存储等持续异常统一接入全局告警中心。
