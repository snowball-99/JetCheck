# 010 背板副场景默认示例数据

## 基本信息

- 状态：设计中，Demo 已实现
- 提出日期：2026-07-13
- 最近更新：2026-07-13

- 相关页面：客户端检测工具、工具配置、相机管理、IO模块管理、检测运行页、检测记录

## 需求背景

1.5 版本主项目是齿轮，副项目包含三羊安全卡扣和背板。为了验证 1.5 的场景化设计不是只适用于齿轮，需要在 Demo 中补充背板这类“单相机、两面采图、全图缺陷检测”的真实业务样例。

背板场景与齿轮差异明显：它不需要先识别多个子区域再检测，而是对上半面、下半面图像直接进行全图缺陷检测。因此运行页和记录详情必须支持“检测结果直接回绘到原图”的表达。

## 默认数据范围

1. 本地模型：
   - 示例-背板缺陷检测，缺陷检测模型。
2. 相机：
   - 示例-背板相机。
3. IO模块：
   - 示例-背板IO，型号 USR-IO808。
   - DI1：周期开始并触发上半面采图。
   - DI2：旋转 180° 到位后触发下半面采图。
   - DO1/DO2/DO3：分别对应 NG/OK/异常灯。
   - DO4/DO5：用于表达气缸旋转与复位信号。
4. 检测工具：
   - 工具名称“示例-背板”。
   - 图像获取项：示例-上半面、示例-下半面。
   - 图像处理：两项均为全图处理。
   - 图像检测：两项均使用背板缺陷检测模型。
   - 判定规则：缺陷数量为 0 时 OK，有缺陷时 NG。
5. 示例图像：
   - `sample-images/背板-上.png`
   - `sample-images/背板-下.png`

## 设计目标

1. 补齐背板副场景的完整默认工具配置。
2. 让背板场景可用于验证全图缺陷检测结果展示。
3. 背板运行页、记录抽屉和详情中的缺陷框都绘制在原图上。
4. 避免背板被误展示为“1 个子图”或“全图 ROI 框”。

## 设计范围

### 本次包含

1. 背板模型、相机、IO模块、检测工具默认数据。
2. 背板上下半面采图项和示例图像。
3. 背板全图处理、缺陷检测和判定规则。
4. 背板检测运行页和记录详情的缺陷框回绘。
5. 旧缓存数据迁移，替换早期错误背板示例图。

### 本次不包含

1. 背板真实旋转气缸联动。
2. 背板真实缺陷模型输出。
3. 背板缺陷类别体系细分。
4. 背板模型训练流程的完整平台端样例。

## 设计结论

1. 背板作为副项目默认工具写入 Demo，用于验证不同于齿轮的全图缺陷检测场景。
2. 背板只有上半面、下半面两个图像获取项，不按角度或相机拆分更多项。
3. 背板图像处理为全图处理，处理后的图像等于原图，不产生可点击子图。
4. 背板缺陷检测结果直接绘制回原图；当存在缺陷时，对应图像项为 NG，周期结果也为 NG。
5. 背板详情页不显示“1 个子图”、全图 ROI 框或“全图”标签。
6. 背板缺陷框使用红色矩形框，贴近真实缺陷检测输出。
7. 背板示例图需要使用真实背板图像文件，不再使用旧的临时占位图。

## 页面与交互规则

### 工具配置

1. 第 1 步图像来源显示上下半面两个图像获取项。
2. 第 2 步图像处理显示全图处理。
3. 第 3 步图像检测使用背板缺陷检测模型。
4. 第 4 步判定规则配置为缺陷数量等于 0。

### 检测运行页

1. 两个检测项平铺展示。
2. 检测完成后显示对应背板图像和总结果。
3. NG 图像直接在主图上显示缺陷框。
4. 点击图像打开整图详情。

### 图像详情

1. 详情只显示整图和缺陷框。
2. 不展示子图列表、子图数量、全图 ROI 框。
3. 图像需要适配容器，不允许溢出画面。

## 数据与权限影响

1. Demo 默认数据新增背板相关模型、相机、IO、工具和记录。
2. 浏览器旧缓存需要通过数据版本迁移补齐或修正背板示例数据。
3. 背板缺陷框坐标为 Demo 示例坐标，仅用于交互验证。
