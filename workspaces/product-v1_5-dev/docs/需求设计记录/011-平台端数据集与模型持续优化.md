# 011 平台端数据集与模型持续优化

## 基本信息

- 状态：设计中，Demo 开发中
- 提出日期：2026-07-13
- 最近更新：2026-07-14
- 对应 Demo：`demo/platform.html`
- 相关页面：数据集、智能标注、数据体检、派生数据集、模型管理、模型版本

## 需求背景

现有平台端以图像库、模型管理和训练记录组织模型训练流程。图像库更接近图像文件夹，灵活但数据散落；模型下的训练记录承担了类似版本的作用，但每次训练仍高度依赖用户手动选择数据、复制训练记录并做增量修改。

随着客户端持续承接采图和检测，训练数据会不断回流。平台端需要从“管理图像文件夹和训练记录”升级为“管理持续更新的数据集和持续优化的模型版本”。同时，平台端仍应保持纯粹的模型训练平台定位，不引入项目、产线或业务场景管理对象。

## 设计目标

1. 将图像库升级为数据集，让用户以一个概念管理样本、标注、质量状态和训练数据版本。
2. 将标注从训练记录中抽离，归属于数据集样本，并在数据集版本中形成可追溯快照。
3. 将模型训练改为引用数据集版本，模型管理聚焦模型定义、模型版本、训练任务和评估结果。
4. 支持辅助标注建议、连续确认、质量检查和必要复核，降低重复标注和低质量标注风险。
5. 支持派生数据集，派生区域既可以来自已有模型推理，也可以来自人工绘制 ROI、固定模板或相似样本复用。
6. 保留从模型出发的轻量入口，避免老用户失去熟悉路径。

## 核心定义

### 1. 平台端边界

平台端不定义“项目”作为核心对象，也不理解齿轮、安全卡扣或具体产线业务。平台端只理解以下对象：

1. 数据集。
2. 样本。
3. 标注。
4. 标注质量状态。
5. 数据集版本。
6. 训练任务。
7. 模型。
8. 模型版本。
9. 评估结果。
10. 模型导出或发布。

业务场景可以通过名称、备注、标签、数据来源和客户端工具配置间接表达，但不成为平台端正式对象。

### 2. 数据集与图像库

不新增独立的“数据资产池”概念。原图像库文件夹升级为数据集：

| 旧概念 | 新概念 |
| --- | --- |
| 图像库文件夹 | 数据集 |
| 文件夹内图片 | 数据集样本 |
| 图像标签 | 样本标签或筛选条件 |
| 上传图像 | 向数据集添加样本 |
| 导出文件夹 | 导出数据集样本 |

数据集既保留文件夹式管理直觉，又增加训练所需的状态、版本和质量控制能力。

### 3. 标注归属

标注主要归属于数据集样本，而不是模型训练记录。原因是标注代表样本真值，模型训练只是使用这些真值。

推荐关系：

```text
数据集样本
  -> 标注
  -> 标注状态
  -> 质量状态
  -> 是否进入数据集版本

数据集版本
  -> 固定样本集合和标注快照

训练任务
  -> 引用某个数据集版本

模型版本
  -> 由训练任务产出
```

这样可以避免同一张图在多个模型训练中重复标注，也能支撑数据持续更新、训练结果追溯和模型版本对比。

### 4. 辅助标注建议

Demo 中不将“预标注”固定定义为模型推理结果，而统一称为辅助标注建议。建议来源包括：

1. 模型建议：由已有模型或历史模型版本推理得到候选框、类别和置信度。
2. 人工 ROI：由用户在原图上绘制有效区域或排除背景区域。
3. 固定模板：相机位、工装和产品姿态稳定时复用固定区域。
4. 相似样本复用：复制上一张或相似图片的标注框，再由用户微调。

辅助标注建议不是样本真值。用户确认或修正后，才成为正式标注。

### 5. 复核

复核不是所有数据的必经流程，而是质量控制状态。以下数据可进入待复核：

1. 模型建议置信度低或存在冲突。
2. 框太小、越界、重复框、类别缺失等质量规则命中异常。
3. 空标注但系统判断可能存在目标。
4. 训练后误检、漏检、低置信度样本回流。
5. 抽检策略命中的关键样本。
6. 新手标注员完成的样本，或多人标注结果不一致的样本。

Demo 暂不实现真实权限，仅表现为复核模式。复核操作包括通过、退回修改、排除样本、修改后通过。

### 6. 派生数据集

派生数据集不是多阶段流程编排器。它表示：基于来源数据集，通过某种区域生成方式和裁剪/变换规则，生成新的数据集。

```text
来源数据集
  -> 区域生成方式
  -> 裁剪/变换规则
  -> 派生数据集
```

区域生成方式包括：

1. 模型推理 ROI。
2. 人工绘制 ROI。
3. 固定模板 ROI。
4. 复用已有 ROI。

注意区分两类 ROI：

1. 训练数据 ROI：用于裁剪训练样本、排除背景、生成派生数据，归属于数据集或派生规则。
2. 推理运行 ROI：用于模型上线后限定推理区域，归属于模型部署配置或客户端工具配置。

### 7. 模型与数据集

模型不拥有标注。模型关联主数据集，并通过训练任务引用数据集版本。

模型侧保留快捷训练入口：

```text
模型 -> 选择数据集或数据集版本 -> 创建训练任务 -> 产出模型版本
```

数据集侧也可发起训练：

```text
数据集 -> 生成数据集版本 -> 训练关联模型 -> 产出模型版本
```

两条入口服务不同用户习惯，但底层对象保持一致。

## Demo 设计范围

### 本次包含

1. 将图像库入口在 Demo 中升级为数据集列表。
2. 数据集列表展示样本、标注、复核、版本和关联模型概览。
3. 数据集详情展示样本列表、状态筛选、质量概览、版本生成和训练入口。
4. 智能标注工作区展示辅助标注建议、确认建议、完成并下一张和质量提示。
5. 数据体检页展示类别分布、异常样本、重复样本和是否可生成版本。
6. 模型训练记录页补充数据集版本、模型版本和指标信息。
7. 派生数据集 Demo 支持“模型 ROI”和“人工 ROI”两种生成方式的模拟。

### 本次不包含

1. 真实后端数据集服务。
2. 真实模型推理、真实预标注和真实图像裁剪。
3. 完整权限系统和复核角色管理。
4. 多阶段流程编排器。
5. 真实部署发布和客户端联动。

## 页面与交互规则

### 数据集列表

数据集列表替代原图像库根页的主心智。每行展示：

1. 数据集名称。
2. 算法任务类型。
3. 样本数。
4. 待标注数。
5. 已确认数。
6. 待复核数。
7. 最新数据集版本。
8. 关联模型。
9. 最近更新。
10. 操作：进入数据集、智能标注、数据体检、训练模型、生成派生数据集。

### 数据集详情

数据集详情保留图像列表/宫格能力，同时增加状态与质量管理：

1. 顶部展示样本总数、待标注、已确认、待复核、已入集。
2. 可按设备、标签、标注状态、质量状态筛选。
3. 批量操作包括确认建议、设为待复核、排除、生成数据集版本。
4. 数据集版本生成时锁定样本集合和标注快照。

### 智能标注工作区

智能标注工作区从数据集进入。辅助标注建议以虚线或浅色框展示，用户确认后转为正式标注。

核心动作：

1. 确认辅助建议。
2. 修正标注框。
3. 完成并下一张。
4. 标记待复核。
5. 排除样本。

### 数据体检

数据体检在训练前展示风险：

1. 未标注样本数量。
2. 待复核样本数量。
3. 类别分布。
4. 小框、越界、空标注等异常。
5. 训练集/验证集划分建议。
6. 是否建议生成数据集版本。

### 模型版本

模型管理页保留模型入口，但训练记录视角升级为模型版本视角。模型版本展示：

1. 模型版本编号。
2. 引用的数据集版本。
3. 样本数和标注数。
4. 训练状态。
5. 评估指标。
6. 操作：查看标注、测试、下载、设为推荐版本。

## Demo 初始数据

平台端 Demo 的默认数据与客户端示例工具保持同一套语义，便于端到端理解：

1. `示例-齿轮`：模拟客户端 A/B 两个相机、0/30/60/90/120/150 六个角度的回流图像。
2. `示例-齿轮齿面识别`：图像分类模型，关联 `示例-齿轮齿面识别数据集`。
3. `示例-齿轮气泡检测`：目标检测模型，关联由齿面 ROI 裁剪生成的 `示例-齿轮气泡检测派生数据集`。
4. `示例-背板`：模拟客户端上下半面采图回流。
5. `示例-背板缺陷检测`：目标检测模型，关联 `示例-背板缺陷检测数据集`。

模型侧“选择数据集训练”入口用于验证新流程：模型不再复制旧训练记录，而是选择数据集版本并生成模型版本。

## Demo 验收标准

1. 用户能从图像库入口理解“数据集”是训练数据的主对象。
2. 用户能看到标注状态归属于数据集样本，而不是某次训练记录。
3. 用户能从数据集详情进入智能标注，确认辅助建议并推进样本状态。
4. 用户能看到数据体检如何影响是否生成数据集版本。
5. 用户能看到模型版本引用数据集版本，而不是复制训练记录。
6. 用户能理解派生数据集既可来自模型 ROI，也可来自人工 ROI。

## 待确认项

1. 平台正式产品中是否将“图像库”直接更名为“数据集”，还是保留“图像库”作为历史入口。
2. 数据集是否必须绑定任务类型和标签体系，是否允许一个数据集服务多个模型。
3. 复核是否需要真实角色权限，还是先作为样本状态能力。
4. 数据集版本是否支持用户手动命名和回滚。
5. 派生数据集生成后是否允许回看来源原图与 ROI。
