## 需求背景

平台端当前以数据集和模型为核心对象，适合熟悉训练流程的用户，但对首次试用的工业用户门槛偏高。许多用户并不理解目标检测、图像分类、分割、ROI、派生数据集等算法或训练概念，他们更自然的表达是“我要检测齿轮上的气泡和划痕”“我要判断卡扣有没有装好”。

因此平台端需要新增「场景库」模块，让用户从典型工业检测场景进入，由系统将检测需求映射为标准化的数据导入、标注、训练、测试和导出流程。

## 产品定位

场景库是平台的低门槛工作流入口，与数据集、模型、客户端平级。

场景库不替代数据集管理，不替代模型管理，也不是项目管理。它只解决一个问题：帮助用户基于工业检测需求，创建并持续完成一条训练流程。

核心逻辑：

```text
场景模板
  -> 我的场景
  -> 引导用户创建/维护数据集、标注、训练任务和模型
  -> 产出一个或多个普通模型
```

齿轮这类多阶段场景最终产出两个普通模型：齿面定位模型、气泡/划痕检测模型。平台端首版不引入“组合模型”或“模型方案”作为新资产类型。

## 核心对象

### 1. 场景模板

场景模板是可复用的工业检测工作流说明和默认配置。

它包含：

1. 场景名称。
2. 检测任务分类。
3. 行业标签。
4. 产品对象。
5. 一句话描述。
6. 数据准备要求。
7. 默认标签。
8. 推荐工作流步骤。
9. 每一步用户需要做什么。
10. 每一步系统会自动生成或记录什么。

场景模板只描述工业问题，不在用户界面中暴露算法类型。模板内部可以映射到目标检测、分类、ROI 裁剪等底层能力。

### 2. 我的场景

我的场景是用户基于某个场景模板创建的轻量流程实例。

它记录：

1. 场景名称。
2. 来源模板。
3. 当前步骤。
4. 完成进度。
5. 关联数据集。
6. 关联模型。
7. 最近更新时间。
8. 下一步入口。

我的场景不是项目管理，不管理客户、产线、工位、验收或交付。它只用于让用户可以跨天、跨阶段回到同一条训练流程继续操作。

### 3. 数据集与模型

数据集和模型仍然是底层正式资产。我的场景只是串联它们。

```text
我的场景
  -> 数据集 A
  -> 模型 A
  -> 数据集 B
  -> 模型 B
```

用户可以从我的场景继续流程，也可以从数据集或模型模块直接进入底层对象。

## 齿轮场景推荐工作流

场景名称：齿轮表面气泡/划痕检测。

场景说明：适用于需要先定位齿面区域，再检测齿面气泡、划痕等缺陷的场景。

推荐流程：

1. 导入完整齿轮图像。
2. 标注齿面区域。
3. 训练齿面定位模型。
4. 使用齿面定位模型生成齿面裁剪图。
5. 在齿面裁剪图中标注气泡、划痕。
6. 训练气泡/划痕检测模型。
7. 分别导出齿面定位模型和气泡/划痕检测模型，并在客户端按顺序配置。

注意：平台端不将这两个模型合并成“组合模型”。场景详情页只提示它们在客户端中的建议执行顺序。

## Demo 实现范围

本轮 Demo 包含：

1. 新增一级导航「场景库」。
2. 新增「场景模板 / 我的场景」两个页签。
3. 展示 6 个首批模板。
4. 支持从模板创建我的场景。
5. 支持查看我的场景详情和步骤进度。
6. 齿轮场景详情中可跳转到关联数据集继续标注。
7. 模型模块保持普通模型列表，不展示组合模型。

本轮 Demo 暂不包含：

1. 完整真实导入流程。
2. 真实训练调度。
3. 自动创建所有数据集和模型的后端服务。
4. 复杂权限和多人复核。
5. 场景模板后台配置器。

## 待确认项

1. “我的场景”的命名是否使用“我的场景”还是“已创建场景”。
2. 模板创建时是否需要用户填写场景名称、检测目标、图像来源，还是首版先使用默认值。
3. 单模型场景和多阶段场景是否共用同一套详情页布局。
4. 场景完成后是否需要显示客户端配置建议页。
5. 后续是否支持复制已有场景继续创建相似流程。
