# 014 客户端算子按需拉取

## 基本信息

- 状态：设计中，Demo 已实现
- 提出日期：2026-07-22
- 最近更新：2026-07-22
- 对应 Demo：`demo/client.html`
- 相关页面：客户端检测工具、工具配置第 2 步图像处理、工具配置第 3 步图像检测、客户端算子选择抽屉

## 需求背景

在 013 平台端算子实例架构中，平台端核心对象是“算子实例”。客户端与平台端统一使用“算子”作为外显名称，不再使用“模型”或“能力”作为同层业务概念。客户端缓存的不是另一个独立业务对象，而是平台算子的部署描述、运行权重和必要资源。

实际使用中，客户端用户更关心“当前工具需要什么算子”。因此更合理的路径是：在配置工具时直接选择本地已缓存算子；如果本地没有，再从平台拉取或导入算子包，而不是先进入独立的算子管理页面维护资源。

## 设计目标

1. 取消“算子管理”作为客户端一级业务入口，降低配置前置成本。
2. 在工具配置过程中按需选择、拉取或导入算子。
3. 保留客户端离线运行需要的本地缓存算子，但不再要求用户主动维护算子列表。
4. 明确平台算子、本地缓存资源、运行权重和客户端处理/检测实例之间的标识关系。
5. 允许处理实例和检测实例先以“空壳算子”存在，未关联平台算子时仍可运行并保留输入。

## 设计范围

### 本次包含

1. 客户端左侧菜单移除“算子管理”入口。
2. 工具配置中统一使用“选择算子”的用户口径。
3. 算子选择抽屉支持查看已缓存算子、从平台拉取、导入算子包。
4. 离线、空间不足、重复版本等异常反馈按算子口径表达。
5. 旧算子管理页面不作为正常业务入口，仅作为后续缓存维护入口的占位。

### 本次不包含

1. 平台端算子实例全量改造。
2. 后端接口、字段和真实资源下载协议。
3. 本地缓存清理、版本回滚、引用分析等完整维护功能。
4. 旧数据结构向算子实例结构的正式迁移脚本。

## 设计结论

1. 客户端不再保留“算子管理”一级菜单。
2. 客户端与平台端统一使用“算子”作为外显名称。
3. 工具配置第 2 步和第 3 步需要算法推理资源时，用户直接点击“选择算子”。
4. 选择抽屉默认展示本地已缓存算子，并提供“从平台拉取”和“导入算子包”入口。
5. 从平台拉取完成后，算子进入本地缓存，并可立即绑定到当前配置项。
6. 导入本地算子包用于离线或现场拷贝交付场景。
7. 本地缓存仍存在，但隐藏在业务路径之后，未来可在设置或 Demo 专用维护区中提供清理能力。
8. 新建处理实例或检测实例时可以暂不关联平台算子。此时实例是一个本地空壳，只保存输入关系，不产生算子推理输出。
9. 后续选择平台算子后，实例保存 `operatorId`、`weightId`、`deploymentId` 和 `configRevision`，后续数据才能自动归入对应平台算子。

## 页面与交互规则

### 页面结构

1. 左侧菜单只保留检测工具、检测记录、相机管理、IO 模块管理等与现场操作直接相关的入口。
2. 工具配置中，图像处理和图像检测配置项显示当前绑定的算子名称、版本、来源和类型。
3. 算子选择抽屉包含：
   - 搜索算子名称或版本编号。
   - 按算子类型筛选。
   - 已缓存算子列表。
   - 从平台拉取入口。
   - 导入算子包入口。

### 操作流程

1. 用户进入检测工具配置。
2. 在需要算法推理的配置项中点击“选择算子”。
3. 若本地已有算子，直接选择并确认。
4. 若本地没有算子，点击“从平台拉取”，选择平台端可用算子版本。
5. 拉取完成后，该算子自动进入本地缓存，并可绑定到当前配置项。
6. 离线场景下，用户可通过“导入算子包”选择本地文件完成导入。

### 状态与反馈

1. 已缓存算子显示来源、版本编号、算子类型、更新时间等信息。
2. 平台算子在拉取中显示“拉取中...”，完成后显示“已缓存”。
3. 当前离线时，平台拉取入口不可用，并提示无法从平台拉取算子。
4. 空间不足时阻断拉取或导入，并提示剩余空间不足。
5. 重复版本导入时阻断，并提示算子版本编号已存在。

### 校验与异常

1. 图像处理 ROI 模式关联算子后，该算子必须支持 ROI 识别及类别输出。
2. 图像处理和图像检测实例未选择算子时仍可保存和运行，但只产生输入，不产生推理输出。
3. 已关联算子但本地资源不存在或损坏时，按“算子推理失败”处理。
4. 算子未提供必要类别时，相关类别选择区域显示为空并阻断关联。

## 数据与权限影响

1. Demo 当前仍复用 `localModels`、`cloudModels` 等内部字段，但前端只显示“算子”。
2. 当前 Demo 已在缓存资源上补充：
   - `operatorId`：平台算子实例 ID。
   - `weightId`：当前使用的权重版本 ID。
   - `deploymentId`：客户端下发部署描述 ID。
   - `configRevision`：运行配置版本。
   - `artifactHash`：本地缓存文件校验值。
3. 本地资源 ID 只标识客户端缓存，不能再作为平台 `operatorId` 使用。
4. 客户端工具配置只保存所引用算子的不可变版本信息，避免平台更新影响本地运行结果。
5. 本地缓存删除前需要校验是否仍被检测工具引用。
